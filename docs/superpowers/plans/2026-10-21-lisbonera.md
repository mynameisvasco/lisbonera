# Lisbonera Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Jellyfin-compatible server backed by Stremio addons, deployable on the Cloudflare Workers free plan, with an Access-protected SvelteKit dashboard.

**Architecture:** `src/worker.ts` is the Worker entry. It sends Jellyfin API paths to a small case-insensitive router under `src/lib/server/jellyfin/` and everything else to the SvelteKit worker generated by `adapter-cloudflare`. D1 holds configuration; the Cache API holds addon responses, resolved stream lists and images.

**Tech Stack:** SvelteKit 3, Svelte 5, TypeScript, adapter-cloudflare 8, Wrangler 4, D1, shadcn-svelte, Tailwind 4, phosphor-svelte, Geist (fontsource), superforms 3 + formsnap 2 + zod 4, Vitest + @cloudflare/vitest-pool-workers, @jellyfin/sdk (types only).

**Spec:** `docs/superpowers/specs/2026-10-21-lisbonera-design.md`

## Global Constraints

- Free plan: ≤45 subrequests (fetch + Cache API) per request via `Budget`; never proxy video bytes.
- All Jellyfin item ids are 32-char lowercase hex.
- Jellyfin API never goes through SvelteKit; `/admin` always does.
- No Lucide imports anywhere (`@lucide/svelte` banned by ESLint); icons from `phosphor-svelte`.
- Fonts: `@fontsource-variable/geist`, `@fontsource-variable/geist-mono`.
- UI copy: terse, no emoji, no gradients, no sparkle/AI iconography, no marketing text.
- Code, comments, docs in English. Svelte 5 runes only.
- Server name `Lisbonera`, product name `Jellyfin Server`, version `10.11.0`.

## Review Focus

- Episode lists with season 0 / missing `season` or `episode` → specials kept as "Specials", entries without numbers skipped (Task 5 test `videosToSeasons skips unnumbered`).
- Non-IMDb ids (`kitsu:1`, `tmdb:2`) → browse and play work, scrobble skipped (Task 8 test `toMediaRef returns null for kitsu`).
- Expired cache between PlaybackInfo and play / unknown `MediaSourceId` → re-resolve, fall back to first source (Task 6 test `stream redirects to first source when id unknown`).
- Authorization header variants (`Emby …`, `MediaBrowser …`, unquoted, lowercase keys) → token found (Task 3 test `extractToken variants`).
- Catalog shorter than requested window / empty catalog → exact `TotalRecordCount`, no extra fetch (Task 5 test `paginate stops on short page`).

### Task 2: Crypto and ids

**Files:** `src/lib/server/crypto.ts`, `src/lib/server/ids.ts`, tests `test/crypto.test.ts`, `test/ids.test.ts`.

**Interfaces:**

- `hashPassword(pw): Promise<string>` (`pbkdf2$100000$salt$hash`), `verifyPassword(pw, stored): Promise<boolean>`, `randomToken(): string` (32 hex), `sha256Hex(s): Promise<string>`, `encrypt(key, plaintext): Promise<string>`, `decrypt(key, ciphertext): Promise<string>`.
- `guidFor(stremioId: string): Promise<string>`; `seasonStremioId(series, season)`, `episodeStremioId(series, season, episode)`; `parseStremioId(id): { kind: 'item' | 'season' | 'episode'; seriesId: string; season?: number; episode?: number }`; `class IdMap { constructor(db); register(entries: { stremioId, type, seriesGuid? }[]): Promise<Map<string,string>>; resolve(guid): Promise<IdRow | null>; flush(): Promise<void> }`.
- Tests: guid stable and 32 hex; `parseStremioId('tt1:2:3')` → episode; `kitsu:100:5` (2 parts after prefix) parsed as item `kitsu:100:5`? → episode ids are always generated by us with `:` count ≥2 after a `tt`-style base; addon-native ids with colons stay `item` unless they came from our generator (resolve via `id_map.kind`, not parsing).
